
# Example Hooks 不提供兼容性承诺

`example_hooks/` 下的代码是示例，用于演示钩子能做什么、怎么写。它不是发布给外部使用的库，因而不对任何外部消费者承诺接口稳定性、版本兼容性或迁移路径。

## Why this is out of scope

示例的价值在于把当前推荐写法讲清楚。若把示例的接口当成契约来维护，示例就会被历史包袱绑住——为了不让某个下游 `TypeError`，得保留旧的参数形状、加版本探测、写迁移说明，最后示例教的是「怎么兼容历史」，而不是「现在该怎么写」。

**示例** 与 **契约** 是两件事。需要稳定接口的场景应该把代码抽成正式模块（带版本号、变更日志、废弃周期），而不是要求示例目录承担这份责任。示例目录不提供这层机制，也不打算提供。

具体到接口变更：示例的函数签名可以随重构直接改。下游若复制了示例代码并长期依赖，那属于下游自行承担的选择；正确的做法是下游 fork 后自己维护，或推动把所需能力提升为正式模块。

## Consequence: example interface changes carry no breaking marker

既然示例不承诺兼容性，示例的接口变更就不标注 `!` / `BREAKING CHANGE`。这类标注会让整个应用进入下一个主版本，而示例的签名变化并不改变应用对外的契约，不值得为此升级主版本。
