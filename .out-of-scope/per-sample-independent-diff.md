# 每条样本独立 diff / 自包含采样

训练采样不改为「每条样本独立求 diff、裁剪坐标只由自身候选与基准决定」的模型；保持一次 Commit 内共享差异区域并集与提前终止（编码缓存与解码缓存也按 Commit 复用）。

## Why this is out of scope

会话本身保证了一个关键不变量：**所有基准都曾是候选**。KEEP 图在被标记时各自产生一条以自己为 candidate 的样本，而一次 Commit 一次性登记会话内全部存活样本并共享同一个并集。因此任意两个基准之间的差异，必然已被其中较晚成为 KEEP 的那条样本 diff 过并纳入并集。提前终止跳过的那次 diff，其区域是 `C△Bj ⊆ (C△B1) ∪ (B1△Bj)` 的子集——前半由当前样本自己计算，后半已被基准之间的历史 diff 覆盖——所以被跳过基准的关键差异不会丢失。对跨 Commit 的 baseline 同样成立：新 Commit 的 candidate 会 diff 过自己当时的全部 baseline，间接覆盖旧 baseline 对之间的差异。用逻辑原型逐像素验证：提前终止与强制完整 diff 的裁剪区域和各块签名逐块一致。

同 Commit 中非当前样本基准的样本也会贡献并集，因此一条样本的 CID 仍依赖提交内顺序——但这在 AI 图像场景下既**有界**又**合理**：

- **全图生成**走整图缩放路径，根本不进 diff/并集；
- **局部重绘始终使用同一蒙版**，所有候选与基准的差异都被限制在蒙版内，并集最大只扩到蒙版边界，而蒙版本身正是用户关心的重绘区域——不存在「放大到无关区域」的问题。候选块与各基准块仍用同一绝对坐标裁剪、逐块对齐，符合训练设计文档对「可直接对比」的承诺。

相反，提前终止有实打实的收益：基准集合随 KEEP 累积，`resolveRegion` 先解码全部基准再逐个 `diffRect`，若第一个 diff 已被并集覆盖就直接返回，跳过其余 N-1 个基准的 imgdiff 计算。改为每条样本独立求 diff 会失去这些收益，并让既有归档的 CID 整体失效，代价与收益不对称。

顺序依赖虽然在 `Record` 的单条签名上不显性，但 `SampleRecorderFactory` 已把并集与缓存的生命周期显式绑定到一次 Commit，跨样本行为由 generator seam 的多调用测试覆盖（提前终止、无基准不污染并集等），测试面是完整的，不存在「隐藏到无法验证」的状态。
