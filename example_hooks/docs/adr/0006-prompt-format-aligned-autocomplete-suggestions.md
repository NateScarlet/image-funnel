# ADR 0006: 补全建议按目标模型的提示词格式输出

## 状态

Accepted

## 背景

`/add` 提交时会按目标模型的提示词格式重排提示词文本（`anima` 转小写并把下划线换空格、`sdxl` 把空格换下划线、`disabled` 跳过）。但补全给出的建议取自 Danbooru 标签原文，一律是下划线形态，用户选中后插入笔记的是下划线，提交时才被改成另一种形态，想直接复制到工程就得手改。

## 决定

**`/add` 的补全建议按目标模型的提示词格式输出，与提交后落盘的文本一致。**

- 仅 `/add` 对齐格式。`/remove` 与 `/adjust prompt` 的补全列出的是工作流中**已存在**的标签文本，其职责是让用户精确匹配既有文本，保持原文。
- 格式化复用提交路径的同一入口，**接受其把推理结果持久化到模型格式配置文件的副作用**。补全文本必须与落盘文本逐字符一致，复用同一实现是唯一能保证这一点的方式；首次推理后该模型即以「配置」来源命中，不再落盘。
- 补全所需的格式解析依赖由组合根注入，主应用数据目录环境变量缺失时直接报错，**不降级为原文**：这是非预期环境。

## 被否决的替代

- **用只读的格式解析避开写盘**：需要另写一条与提交路径平行的格式化路径，两侧行为可能漂移，补全与落盘不一致的风险大于一次写盘。
- **数据目录环境变量缺失时降级为原文**：缺失说明环境非预期，应快速失败。
- **把格式对齐扩展到 `/remove`、`/adjust prompt`**：会让用户选不中要删除的既有标签。
