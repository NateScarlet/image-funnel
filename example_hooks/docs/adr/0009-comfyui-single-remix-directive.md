
# ADR 0009: ComfyUI 编辑采用单一 /remix 指令与变体矩阵

## 状态

Accepted

## 背景

ComfyUI 工作流的各类编辑——增删提示词、调整提示词/Lora/CFG/长宽比、重放历史移除——共享同一套目标定位（`CLIPTextEncode` 节点与区域）、同一套变体生成能力、同一套提交与操作历史机制，且经常需要组合发生（如先移除再加）。

## 决定

**ComfyUI 编辑由单一 `/remix` 笔记指令表达，各编辑以旗标区分；多个各自产出多档的编辑维度之间取笛卡尔积，每个组合是一个独立变体。**

- 不含任何编辑旗标时，`/remix` 等价于直接入列生成。
- 变体有两个来源：参数内部的多档表达式（如 `0.5:1.0:0.1`、`+3`）展开为多档；互斥旗标（`--cfg` / `--aspect`）重复调用视为多值，各产一个变体。不同旗标之间取笛卡尔积。
- 可累加旗标（`--add` / `--remove` / `--lora`）重复调用是累加，合并进同一变体；想要两个不相干的变体，写两条 `/remix`。
- 每个变体从基线工作流出发计算，不继承其他变体的中间状态。
- 移除动作是全局操作，不提供范围限定。
- `/set-model-format` 不并入：它写的是全局模型格式配置，不作用于任何图片的工作流、也不依赖图片上下文，并入会让「无编辑旗标 = 入列生成」出现例外。
- `--add` 的 tag 与权重靠位置和引号区分，不设显式 `--weight` 旗标：tag 含空格时用引号聚合；恰好一个 tag 时末尾 token 可解析为权重表达式，此时为调整权重，否则为新增；多 tag 时末尾出现权重表达式直接报错。

## 被否决的替代

- **保留多个独立指令各自触发**：组合编辑需要写成多行、触发多轮，产生中间态提交。
- **单指令但变体按顺序串联而非笛卡尔积**：结果依赖变体的书写顺序，不可预测。
- **变体原地变异、继承上一个变体的中间状态**：相对权重表达式（如 `x-0.1`）的含义会随变体顺序漂移。
- **移除动作保留范围限定（`--node` / `--region` / `--all`）**：只要允许限定范围，节点间就可能残留重复标签，删除目标不达成。
- **用显式 `--weight` 旗标区分新增与调权**：为低频的调权场景引入一个用户每次新增都要理解的旗标；位置与引号分流配合自动补全自动加引号，日常输入无需额外旗标。
- **多 tag 末尾权重按规则猜测语义**：多值加权重无既有语义可依，猜测会在用户写错时静默产生非预期结果，故报错。
- **把 `/set-model-format` 一并并入 `/remix`**：它是全局配置写入，与「编辑某张图的工作流并提交」不同源；并入后用户得从「改配置」和「改图」两类意图中分辨同一个指令。
- **可累加旗标重复调用各产一个变体**：会让 `--add a --add b` 与 `--add a b` 语义分裂，用户得记住两套写法；把「多个目标」与「多个变体」两种意图都压在重复调用上，只会让两者都难以表达。
