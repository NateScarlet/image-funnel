
# ADR 0009: ComfyUI 编辑采用单一 /remix 指令与变体矩阵

## 状态

Accepted

## 背景

ComfyUI 工作流的各类编辑——增删提示词、调整提示词/Lora/CFG/长宽比、重放历史移除——共享同一套目标定位（`CLIPTextEncode` 节点与区域）、同一套变体生成能力、同一套提交与操作历史机制，且经常需要组合发生（如先移除再加）。

## 决定

**ComfyUI 编辑由单一 `/remix` 笔记指令表达，各编辑以旗标区分；多个各自产出多档的编辑维度之间取笛卡尔积，每个组合是一个独立变体。**

- 不含任何编辑旗标时，`/remix` 等价于直接入列生成。
- 变体有两个来源：参数内部的多档表达式（如 `0.5:1.0:0.1`、`+3`）展开为多档；互斥旗标（`--cfg` / `--aspect`）重复调用视为多值，各产一个变体。不同旗标之间取笛卡尔积。
- 可累加旗标（`--add` / `--remove` / `--lora`）重复调用是累加，合并进同一变体；想要两个不相干的变体，写两条 `/remix`。
- 每个变体从基线工作流出发计算，不继承其他变体的中间状态。
- 移除动作是全局操作，不提供范围限定。
- `/set-model-format` 不并入：它写的是全局模型格式配置，不作用于任何图片的工作流、也不依赖图片上下文，并入会让「无编辑旗标 = 入列生成」出现例外。
- `--add` 的 tag 与权重靠位置和引号区分，不设显式 `--weight` 旗标：tag 含空格时用引号聚合；恰好一个 tag 时末尾 token 可解析为权重表达式，此时为调整权重，否则为新增；多 tag 时末尾出现权重表达式直接报错。

## 被否决的替代

- **保留多个独立指令各自触发**：组合编辑需要写成多行、触发多轮，产生中间态提交。
- **单指令但变体按顺序串联而非笛卡尔积**：结果依赖变体的书写顺序，不可预测。
- **变体原地变异、继承上一个变体的中间状态**：相对权重表达式（如 `x-0.1`）的含义会随变体顺序漂移。
- **移除动作保留范围限定（`--node` / `--region` / `--all`）**：只要允许限定范围，节点间就可能残留重复标签，删除目标不达成。
- **用显式 `--weight` 旗标区分新增与调权**：为低频的调权场景引入一个用户每次新增都要理解的旗标；位置与引号分流配合自动补全自动加引号，日常输入无需额外旗标。
- **多 tag 末尾权重按规则猜测语义**：多值加权重无既有语义可依，猜测会在用户写错时静默产生非预期结果，故报错。
- **把 `/set-model-format` 一并并入 `/remix`**：它是全局配置写入，与「编辑某张图的工作流并提交」不同源；并入后用户得从「改配置」和「改图」两类意图中分辨同一个指令。
- **可累加旗标重复调用各产一个变体**：会让 `--add a --add b` 与 `--add a b` 语义分裂，用户得记住两套写法；把「多个目标」与「多个变体」两种意图都压在重复调用上，只会让两者都难以表达。

## 修订

后续增加了空转保护：入列前把即将提交的 prompt（ComfyUI API 结构）与预处理完成、编辑之前的基线深比较，完全一致时跳过入列，避免固定种子下重跑出一张与源图相同的图。`--no-skip` 仍然放行。见 [Issue #150](https://github.com/NateScarlet/image-funnel/issues/150)。

由此「不含编辑旗标时等价于直接入列生成」不再成立：不含编辑旗标时不会无条件入列，是否入列取决于 prompt 相对基线是否发生变化。

## 修订 2（新增 `--branch` 旗标，见 #168）

新增 `--branch <suffix>` 旗标，使生成结果落到按 `/branch` 命名规则（`<当前目录名>,<suffix>` / 根目录 `<suffix>`）推算的新目录，而非图片当前目录，省去「先渲染、事后 `/branch`」两步。取舍：

- **`--branch` 不算「编辑项」**：仅带 `--branch` 而无其它编辑时，prompt 相对基线无变化，仍受入列前空转保护约束（需 `--no-skip` 才重出）。否则固定种子下会把源图原样重出到新目录，与空转保护的初衷相悖。
- **`--branch` 显式优先于 `HOOK_OUTPUT_DIR`**：一旦写了 `--branch`，输出目录以它为准，连 `:inherit:` 也被覆盖。`HOOK_OUTPUT_DIR` 的语义是「全局覆盖默认落盘位置」，而 `--branch` 是单条指令更明确的意图。
- **目标目录已存在时正常写入、不报错**：保证失败重试与幂等重跑不卡住；「创建新分支」描述的是命名方式（带 `当前目录名,` 前缀的同级目录），不是「目录必须不存在」。
- **只加在 remix 子命令**：queue 由钩子直接调用、不传选项，若要让每次入列都 branch 会污染其它触发场景，故不加。

## 修订 3（新增 `--current`，种子改为按 job 生效，见 #173）

新增 `--current` 旗标：只处理笔记配套的那张图片（钩子上下文注入的图片路径），不再按 `HOOK_IMAGE_RATING` 筛选；集合为空时报错并保留指令行。理由：微调工作流里用户已经显式指认目标，评分筛选是目录批量选取的启发式，不该反过来推翻显式意图；静默退回目录批量会让「只处理这一张」变成批量处理。

种子语义整体改为以 job 为单位：

- 种子是每个 job 的取值：job 1 沿用源图种子，job 2..N 各取一个新种子，同一 job 内所有变体共用该值。变体档位不再影响种子。
- 只有重新入列（无编辑项）与 `-u` 会让 job 1 也换种子。
- 每轮 job 先求一份基线（至多一次种子更新）并按 prompt 去重，因此完全 fixed 的工作流只产生一份基线，`-j N` 不会排出 N 张相同的图（重新入列仍会被空转保护跳过一次都不发）。
- 变体相对所属 job 的基线判定是否产生改动，无改动变体整轮不参与；无编辑项时基线本身即变体。最终提交仍与源基线比较，fixed 工作流上的重新入列因此仍被空转保护跳过。`-S` 绕过以上全部判定。

这有意取消了旧 `/adjust` 的「第 2 档起换种子」，也不再保证与旧指令的产物等价：变体之间换种子会让参数扫描的差异与噪波差异混在一起，而这正是要避免的。需要更多噪波样本用 `-j`，需要 job 1 也换种子用 `-u`。

修订 2 中「仅带 `--branch` 而无其它编辑时仍受空转保护约束」只对 fixed 种子工作流成立：随机种子工作流在重新入列时会更新种子，prompt 与基线不同，照常提交。
