# ImageFunnel 外部钩子（Example Hooks）领域语言

本上下文定义了 `example_hooks` 模块特有的、主应用无需感知的语义和概念，主要涉及通过外部 Python 脚本和 ComfyUI 交互来扩展主应用的功能。

## 核心概念

**钩子配置 / Hook Config**
外部钩子的声明，包含元数据、可执行脚本命令行、环境配置以及触发条件（例如在提交会话后触发）。

**指令 / Directive**
在笔记（Note）中以 `/` 开头的斜杠指令（例如 `/branch`, `/remix`）。钩子服务在触发时扫描笔记并匹配相应的指令以提取参数。

**工作流提示词操作 / ComfyUI Workflow Prompt Action**
与 ComfyUI 交互的特定动作类型，包含：

- **添加提示词 / Add Prompt**: 给符合特定评分的图片所关联的 ComfyUI 工作流添加新的提示词标签并发送到生成队列。
- **调整权重 / Adjust Weight**: 调整工作流中特定 Lora 的权重或提示词的比重。
- **移除提示词 / Remove Prompt**: 自动剔除工作流中的某些标签或节点。

**重混 / Remix**
把一次生成所需的多项 ComfyUI 编辑（增删提示词、调整提示词/Lora/CFG/长宽比、重放历史移除）合并为单个笔记指令表达，一次产出这些编辑的合并结果。移除动作没有范围概念，作用于工作流中所有 CLIPTextEncode 节点。取舍与理由见 [ADR 0009](docs/adr/0009-comfyui-single-remix-directive.md)。

**变体矩阵 / Variant Matrix**
重混中多个各自产出多档的编辑维度（如多个长宽比 × 多个权重档）之间取全部组合，每个组合是一个独立变体、各自入列；同一维度内的多项编辑合并进同一变体，某维度无实际变化时视为恒等。每个变体都从基线工作流出发，因此相对权重表达式的含义不随变体顺序漂移。

**Danbooru 标签自动补全 / Danbooru Autocomplete**
ComfyUI 提示词编辑时的输入联想，包含两种能力：按关键字给出候选标签（搜索），以及按已有标签推荐关联标签（关联联想）。候选标签受类目与 NSFW 开关约束。`/remix --add` 在无输入、工作流含区域标记、且尚未指定目标时，优先直接建议全部可用区域；选定目标或工作流无区域后才进入关联标签推荐。

**强匹配 / Exact Match**
查询与标签名或某个中文别名精确相等。命中强匹配即认为用户意图明确，**字面匹配**与**语义层**都会据此让路（语义层不再追加），因此强命中路径的可用性不受语义层依赖影响。

**字面匹配 / Literal Match**
完全离线的字符匹配：由最严格到最宽松逐层放宽（精确 > 中文别名精确 > 前缀 > 子串 > 笔误容忍），同层按标签热度排序。无需任何外部服务。

**语义层 / Semantic Layer**
**仅在字面匹配没有任何强匹配时**追加的召回阶段：把查询与标签都表示为向量，按相似度找出语义相近的标签，补充「只记得语义、说不出标签名」的场景。召回结果经 NSFW 过滤与热度加权后并入同一份排序——因此字面命中并非总是排在语义命中之前，强相似度的语义命中会排在宽松的字面命中之上。语义层只作用于搜索，**关联联想**行为不变。

**标签向量 / Tag Embedding**
标签在语义层中参与相似度比较的向量表示，按标签名、中文名与释义分别生成。

语义层需要**标签向量产物**与**可达的嵌入服务**同时成立才激活；缺任一时补全完全退回纯字面匹配，对未配置用户零行为变化。嵌入服务超时或失败时本次查询跳过语义层，仍返回字面结果并附一条错误提示，补全始终可用。取舍与理由见 [ADR 0005](docs/adr/0005-remote-openai-compatible-embeddings-for-danbooru-semantic-layer.md)。

**目录分流 / Branch**
根据指令参数将筛选保留的图片及配套的 XMP 文件，移动到同级按规则命名的子目录中，以实现图片的物理归类。

**输出目录调整 / Output Directory Adjustment**
ComfyUI 钩子在提交前把工作流输出节点的输出位置调整为图片当前所在目录。输出文件**总是直接落在图片当前目录下，不创建任何子目录**。约束：**不得静默丢弃原有路径数据**（直接取 basename 是错误做法）；workflow 模板与 prompt 求值结果必须保持一致（prompt 不能持有 workflow 无法复现的值）。

**ComfyUI 模型提示词格式 / ComfyUI Model Prompt Format**
某个模型期望的提示词标签语法，在笔记中通过 `/set-model-format` 指令配置。三种取值：`anima`（普通标签小写且以空格分隔，`score_*` 评分标签保留下划线）、`sdxl`（标签以下划线连接）、`disabled`（跳过一切重排，作为 opt-out）。

**格式键 / Format Key**
用于确定提示词格式的模型标识，即提示词编码节点（`CLIPTextEncode`）实际使用的文本编码模型。

**格式推导 / Format Derivation**
从格式键到生效格式的判定：显式配置优先，其次按提示词推断，最后回落到默认格式。

**目标提示词节点 / Target Prompt Node**
一次 `/remix` 新增标签或调整标签权重的请求最终会写入的 `CLIPTextEncode` 节点。确定方式与提交路径一致：显式指定的目标优先，未指定时按正/负向取默认区域，多目标时取第一个目标。新增标签的补全建议插入文本按该节点所属模型的提示词格式重排，因此与同一输入提交后落盘的文本形态一致；移除与提示词调权的建议给出的是工作流中已有原文，保持不变。

**取消 / Cancellation**
常驻补全中请求方不再需要某次结果的信号（`$/cancelRequest`）。接收方尽力尽早停止无谓工作并中止在途网络请求，但不承诺强制中断，只保证不再回传该结果。
_避免_: Abort、Terminate（暗示强制中断，本语义不承诺）

**建议文本格式化 / Suggestion Text Formatting**
把补全候选标签转成可直接插入的文本：先按目标提示词节点的模型格式重排，再按重排结果决定是否用引号包裹（`anima` 把下划线换成空格后会新增引号需求）。展示用文本保持原文含中文名。已见提示词同样重排到目标格式后再比对，否则建议被格式化后与原文形态不同，「(已有)」标记会失效。取舍与理由见 [ADR 0006](docs/adr/0006-prompt-format-aligned-autocomplete-suggestions.md)。
