
# ADR 0008: 钩子快捷键冲突时可见降级

## 状态
Accepted

## 背景

钩子可在 `[on.image_dispatch]` 段声明快捷键（如 `hotkeys = ["F5"]`），按下即按当前筛选
上下文派发该钩子。这些键由用户在 TOML 中自由填写，因此可能与前端 `useHotkeys` 已注册的
应用自身快捷键，或与另一个钩子的快捷键相撞。

冲突无法在配置期拦截（钩子经 GraphQL 异步加载，且用户可随时改配置），只能在注册期发现。

## 决定

**冲突的钩子键采取可见降级：不注册 handler（按下不派发、不拦截任何事件），但仍在快捷键
说明列表中以错误样式呈现并标注 `[冲突]`。冲突判定范围仅限应用内已注册的快捷键。**

判定按逐键粒度进行：同一钩子内某个键冲突不影响其余键正常注册。

## 考虑过的选项

- **报错并拒绝加载该钩子配置**：用户仅配错一个键就损失整个钩子，代价与错误不成比例；
  且配置错误并非启动期可一次性发现，报错会让应用无法使用。
- **仍注册但优先级低于应用键**：该键在某些作用域下仍可能触发钩子，用户看到的「无效」
  标注会撒谎；且引入静默的顺序依赖，用户无法从界面理解为何某个键时灵时不灵。
- **静默跳过（用户不可见）**：用户按下无反应又找不到原因，是最差的诊断体验。
- **纳入浏览器/系统级快捷键检测**：前端无法可靠探测这些键是否被占用，纳入只会产生
  假阴性，故排除。
