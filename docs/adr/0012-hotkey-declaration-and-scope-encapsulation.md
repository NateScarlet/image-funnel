# ADR 0012: 快捷键声明统一与作用域栈内聚

## 状态
Accepted

## 背景

快捷键系统用一个 `enabled` 字段同时承载布尔开关与「带上下文的谓词」，派发器靠 `enabled.length > 0` 判断该按哪种方式调用，带参函数会静默绕过默认作用域匹配；同一判断在派发器里重复两处，帮助列表又用 `toValue` 无参调用，三者对同一声明的启用结论可能不一致。这使「是否绕过作用域匹配」藏在参数个数里，类型签名不透露该行为。

同时，全局作用域栈直接导出为可变 `ref`，外部调用者通过读数组长度判断是否处于作用域内；声明列表也以可变 `ref` 导出。作用域与冲突解析的边界不够内聚。

## 决定

1. **统一领域概念「快捷键声明」**：按键、展示分类、启用条件与生效作用域共同构成一条声明（术语见 `GLOSSARY.md`）。应用自身快捷键与外部钩子快捷键都是声明，仅声明来源不同。
2. **`enabled` 拆为两个字段**：`enabled` 只作启用开关；`enabledWhen` 是显式谓词。二者**都参与作用域匹配**，不存在「带参即绕过」的语义；arity 重载与鸭子类型一并消除，派发器与帮助列表共用同一个启用判定函数。
3. **作用域栈退居模块内部**：外部不再拿到可变的作用域栈，改由语义化只读接口访问；谓词拿到的上下文为只读视图。声明列表也收为只读，避免外部修改。
4. **不重开 [ADR 0008](./0008-hook-hotkey-conflict-visible-degradation.md)**：冲突的钩子键「不派发、标注 `[冲突]` 仍展示」的可见降级语义不变；本决定只调整作用域匹配的位置与启用判定的表达，不改变冲突判定结果。

## 考虑过的选项

- **保留单字段，调用时永远传上下文**：能去掉 arity 分支，但「谓词绕过作用域匹配」仍隐藏在用法里，类型签名依旧不表达该行为。拒绝。
- **保留单字段，谓词与作用域匹配相与**：行为最安全，但改写了当前无人使用的带参谓词语义，且与「显式表达差异」的目标相比可读性更差。拒绝。
- **把谓词上下文收窄为 `topmostScope` + `hasActiveScope`**：进一步隐藏作用域栈，但损失谓词判断所需的表达能力。拒绝，改用只读视图。
- **帮助列表按当前作用域过滤，只显示当下可触发的声明**：会改变用户可见行为（其它作用域的快捷键从列表消失），超出本 issue 范围。拒绝。
- **重命名/删除 `activeHotkeys` 导出**：issue 未要求改声明列表的导出面，收为只读即可，避免范围蔓延。拒绝。

## 后果

- 所有快捷键注册点需整体迁移到新接口；不保留兼容别名或 arity 嗅探。
- 未来出现按参数个数分派、鸭子类型判断或重新导出可变作用域栈的改动，应视为对本 ADR 的回归。
- 验收覆盖 `enabledWhen` 与作用域的关系：谓词不绕过作用域匹配，且派发与帮助列表对同一声明得出一致结论。
- ADR 0008 的冲突可见降级不受影响；冲突判定仍按逐键粒度、同一声明的多个绑定互不撞键。
